The angle-bracketed bundle IDs and paths above are neutral schema placeholders. Replace every one
with exact values from component_catalog.json; never submit a placeholder literally.
component_coverage must cover every catalog bundle exactly once. direct_assessment must be completed
before relation for every component. Allowed direct-assessment signals are capability,
semantic_domain, and reuse_interface. verdict match requires matched_entities and catalog_signals
plus an exact published entrypoint and concrete reachability probe, and forces relation direct. A
probe shows an existing entrypoint
receiving, storing, dispatching on, or serializing the exact introduced representation; it remains
a match when that call currently fails, succeeds through an existing path, or chooses the wrong
fallback. can_invoke_with_variant answers only whether the exact representation can be supplied to
or held by the entrypoint before judging its outcome; true forces verdict match and relation direct.
verdict no_match requires both
lists to be empty and forbids relation direct, but it must still name the closest published
entrypoint, set can_invoke_with_variant false, and test the strongest counterfactual probe against
that entrypoint. Allowed relations
are direct, protocol, and none. Allowed relation catalog_signals are
capability, semantic_domain, extension_trigger, consumers, reuse_interface, and boundary, and every
cited field must be non-empty in that component's catalog.
Non-none entries require at least one exact changed entity and one catalog signal. None entries
require empty changed_entities and catalog_signals. Do not make final selection judgments in this
file. At most eight entries may use a non-none relation.

The angle-bracketed bundle IDs and paths in this schema are neutral placeholders. Replace every
one with exact catalog and library values; never submit a placeholder literally.
The selection change_model must exactly match coverage.json. Representation changes require at
least one introduced_or_changed_variants entry. These entries describe the repository-visible
variant itself, not merely the failing function's handling of it. Each component_assessments relation
must equal the corresponding coverage relation. Non-none coverage entries must use decision
shortlist; none entries must use decision reject. shortlisted_bundle_ids must contain exactly the
non-none coverage IDs. Compute coverage_sha256 only after coverage validation succeeds.
shortlist_reviews must cover every shortlisted component exactly once. Allowed coverage verdicts
are confirmed, refuted, and duplicate. Confirmed requires decision select. Refuted and duplicate
require decision omit. A duplicate review must name another shortlisted component in duplicate_of,
and that target must be selected; duplicate_of is null otherwise. Every review requires exact
evidence from that component's detailed files. The selected bundle IDs must exactly match confirmed
review entries. A protocol path is not refuted merely because it is absent from the traceback.
A component with published protocol_status confirmed cannot use the refuted verdict; it must be
confirmed or duplicate. A genuine contradiction is a component-publication defect, not a retrieval
rejection.

During coverage, test direct capability and semantic-domain inclusion before consumer paths. If an
introduced or changed representation belongs to the category explicitly covered by a component's
capability or semantic_domain, relation must be direct even when the task traceback and named
consumers do not mention that representation. Do not use whether the component needs modification
as the coverage criterion.

propagation_checks are a required implementation handoff, not another selection pass. Generalize
each introduced variant into a role-independent carrier, then inspect the selected detailed source
for every sibling operation that can receive that carrier and every applicable argument position.
Do not limit a carrier to the task-named method. Each check must cite exact selected-component
evidence, and the checks together must cover every introduced variant and every selected component.
Write symbols and argument_positions as an executable test matrix, not as broad module names or
questions for the Task Agent.

Allowed change kinds are representation, validation, dispatch, serialization, identity,
persistence, state, lifecycle, construction, interface, behavior, and other. The
component_assessments list must cover every bundle ID from the catalog exactly once. Allowed
relations are direct, protocol, and none. Allowed decisions are shortlist and reject. The
shortlisted_bundle_ids list must exactly match the shortlist decisions and may contain at most
eight IDs. Every selected bundle must first be shortlisted.

Allowed delivery modes are direct_reuse and reference_pattern. Evidence paths are relative to
/component-library. An empty selected list is valid when no component adds substantial information
or reusable work beyond the task baseline. Do not propose a patch or modify the component library.
